# Repository Guidelines

## Project Structure & Module Organization
- Source: `src/tem_pad/` (`cli.py`, `config.py`, `models.py`, `storage.py`, `state.py`, `doctor.py`, `collectors/<source>.py`). Installed as the `tem-pad` console script (`[project.scripts]`).
- Tests: top-level `tests/` with `test_*.py` files and `tests/fixtures/<source>/` holding sanitized sample outputs (no secrets, no personal data). `tests/` has no `__init__.py` (pytest `--import-mode=importlib` + `pythonpath = ["."]`, so `from tests.conftest import ...` works).
- Deployment assets: `compose.yaml` (Loki + Grafana, bound to 127.0.0.1), `deploy/alloy/config.alloy`, `deploy/loki/config.yaml`, `deploy/grafana/{provisioning,dashboards}`, `deploy/launchd/` (LaunchAgent plists, sudoers example, installer), `deploy/sample/events/` (sample JSONL regenerated by `scripts/make_sample_events.py`).
- User docs: `README.md`, `docs/architecture.md`, `docs/log-schema.md`, `docs/setup.md`, `docs/implementation-notes.md` (external-spec assumptions vs. what was verified), `docs/config.example.toml`. Comments and docs are written in Japanese.
- Runtime data (`events/`, `raw/`, `state/`) lives in `~/.local/share/tem-pad/` and is git-ignored; never commit real logs. This repository is public — no hostnames, tokens, vault/item names, or other environment-specific values in code, fixtures, or docs.
- Shared knowledge: `docs/knowledge/` — an OKF bundle (ADRs, runbooks, research) for decisions not obvious from the code. Start at `docs/knowledge/index.md`.
- Tooling: `pyproject.toml` manages deps and tasks; `uv.lock` pins versions; `.pre-commit-config.yaml` defines pre-commit hooks (run via prek).
- Containers: the Dev Container is Docker Compose based (`.devcontainer/compose.yaml` + `devcontainer.json`; per-user diffs go in the git-ignored `.devcontainer/compose.local.yaml`) and is also where AI agent CLIs (Claude Code, Codex, GitHub CLI) are layered in via Dev Container Features and post-create hooks; it also inherits host config — global gitignore, git identity (user.name/email), and Claude Code settings/statusline — staged by `.devcontainer/initialize.sh` and seeded by `.devcontainer/post-start.sh`. The container's `.venv` and uv cache live in named volumes so platform-specific binaries never clash with the host's. A separate set of kits for [Docker Sandboxes](https://docs.docker.com/ai/sandboxes/) (`sbx`) lives in `.sandbox/` — a microVM with deny-by-default networking for unattended agent runs, launched from the host (see `.sandbox/README.md`).

## Build, Test, and Development Commands
- Install (local uv): `uv sync` (dev deps included).
- Run tasks (local): `uv run task <name>` (e.g., `uv run task test`).
- Common tasks (via Taskipy):
  - `task lint`: Ruff + Pyright checks.
  - `task fix`: Ruff autofix.
  - `task format`: Ruff formatter.
  - `task test`: Run pytest.
  - `task test_cov`: Pytest with coverage (HTML at `htmlcov/`).
- Dev container (VS Code): “Reopen in Container”, then run `task ...` in terminal.
- Loki/Grafana stack: `cp example.env .env && docker compose up -d` (see `docs/setup.md`).

### Pre-commit Hooks
Hooks defined in `.pre-commit-config.yaml` (check-only, no auto-fix):
- **ruff-check** / **ruff-format**: lint and format check on staged files.
- **pyright**: whole-project type check when Python files are staged.
- **uv-lock-check**: verifies `uv.lock` is in sync when `pyproject.toml` changes.

Setup is automatic in the Dev Container (post-create). Elsewhere, [install prek](https://github.com/j178/prek?tab=readme-ov-file#installation) and run `prek install`.

## Coding Style & Naming Conventions
- Python 3.12+ (dev environment 3.14), standard library only at runtime, 4-space indentation, type hints required (Pyright strict). Ruff line length is 100.
- Lint/format: Ruff is the single source of truth (`task lint`, `task format`).
- Docstrings: Google style (configured via Ruff/pydocstyle).
- Naming: modules/packages `snake_case`; classes `PascalCase`; functions/vars `snake_case`.
- Keep public APIs small; prefer pure functions and minimal side effects.

## Testing Guidelines
- Framework: Pytest with simple `assert` style.
- Location/naming: `tests/test_<module>.py`, tests `test_*`. Collectors are tested against `tests/fixtures/` with the external CLI/API stubbed (`monkeypatch` of `run_command` / `TailscaleClient`); tests never contact real services.
- Do not add `__init__.py` to `tests/`.
- Never store secrets or personal identifiers in fixtures; sanitize real outputs before adding them.
- Coverage: use `task test_cov`; include edge cases and type-related tests.
- Fast tests by default; mark slow/external I/O as separate or mock.

## Commit & Pull Request Guidelines
- Commit style: Prefer Conventional Commits when possible
  - Examples: `feat: add greeting cli`, `fix: correct None handling`, `chore: update uv.lock`.
- Before PR: run `task lint` and `task test` locally/inside container and fix issues (the prek pre-commit hooks catch most lint/type issues at commit time).
- PR description: purpose, summary of changes, how to test, related issues (`Closes #123`).
- Include screenshots or logs when changing behavior or CLI output.

## Security & Configuration Tips
- Do not commit secrets; prefer env vars and Compose overrides. tem-pad itself reads secrets via `SecretRef` (env / command / file) and must never log, print, or write them to `raw/`.
- Loki/Grafana bind to 127.0.0.1 only; do not expose them on 0.0.0.0. Do not mount the Docker socket or the host filesystem into the stack.
- **Check the environment first:** if `pass-cli` is not on PATH, you are in a Docker Sandboxes (`sbx`) microVM rather than the Dev Container, and the three pass-cli bullets below do not apply. There, GitHub authentication is injected as an HTTP header by the host-side proxy and `GH_TOKEN` holds a sentinel — never try to obtain the real token value. See `.sandbox/README.md`.
- Task secrets (API keys, tokens) come from Proton Pass via `pass-cli`, never from ambient env. Run commands that need them as `PROTON_PASS_AGENT_REASON="<why>" pass-cli run --env-file .env -- <cmd>` (`.env` holds only `pass://` references; copy from `example.env`).
- If any `pass-cli` command fails with an auth error — or there is no active session (`pass-cli info` fails) — run `.devcontainer/pass-relogin` and retry. It restores the session (and seeds `gh auth` when missing) from a token already provisioned in the container.
- Never read, print, or copy `~/.local/state/proton-pass-agent/pat` — you never need the token value itself; `pass-relogin` handles it.
- Pin dependencies via `uv.lock`; update with care (`uv sync --upgrade`).
- CI (`.github/workflows/ci.yml`) runs lint, type check, and tests in a single job; keep the pipeline green before merging.
